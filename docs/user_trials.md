# Independent first-use trials

Current status: **not measured**. Author-local domain trials, automated tests and
GPU/portable acceptance runs are recorded under their actual evidence categories.

A volunteer first-use session should use a released bundle and public or
synthetic paired data. Record, with consent:

1. Release/asset SHA256, OS, browser and selected edition.
2. Whether the participant has contributed to this project or received setup help.
3. Time to explain the software's purpose, run the example, import paired data,
   choose rules and save/replay a report.
4. Task completion, errors, requested help and abandonment. Retain failures.
5. Whether the participant correctly distinguishes protocol sensitivity from
   statistical uncertainty and understands what the shared report contains.
6. A short participant comment and agreed public/private attribution.

Start with three to five volunteers from the intended audience to find concrete
usability problems. Treat this as exploratory feedback. Report the task, assistance
and denominators beside outcomes; do not infer population success rates from a
small convenience sample. Repeat failed tasks after fixes with the new version
and keep the original outcomes.

Keep raw screen recordings and private datasets outside the public repository.
Publish a consented aggregate or de-identified minimal issue. An AI agent replaying
the workflow is an automation check. Someone using maintainer-guided setup is
an assisted trial. Neither should be relabeled independent unassisted use.
